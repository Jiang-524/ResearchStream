# experimentRecord：方法笔记、实验结果与跨项目数据对比

日期：2026-10-12

状态：页面方案已获用户认可；本文件整理新增的坐标映射与跨项目对比要求，待书面设计确认。

## 目标与约束

新增主导航入口 `experimentRecord`，路由 `/experimentrecord/`。沿用 ResearchStream 的 Markdown、主题切换、中英文界面、全文搜索、摘要卡片与 Series 管理。

使用现有 Astro 静态站和 GitHub Pages。由本地 AI 整理笔记、CSV、图片、视频及元数据后提交 GitHub；不新增云端定时任务、数据库、登录或在线持久化编辑。

用户已确认两类内容需求：一份长期维护的方法主笔记，以及该方法下多次实验的结果。补充要求是 CSV 坐标不依赖固定列名，并可在“数据对比”中跨项目选择不同实验、不同 CSV 的曲线。

## 内容层级与稳定编号

- 项目：一篇方法/论文主笔记，对应一个稳定目录 slug 和站内唯一文章 ID。
- 实验：项目中的一次有明确配置和目标的运行，有稳定 `id` 和正整数 `number`。
- CSV：实验中的一个数据文件，有稳定 `id` 和正整数 `number`，可以包含多个指标。
- 指标：CSV 中可选的一条纵轴数据序列，有稳定 `id`、显示名、列映射与单位。

实验类型固定为 `reproduction`（复现）或 `improvement`（改进）。同一项目可以包含两种实验，项目卡片显示其配置的类型标签；它们和自由 tags 分开存储，但均参与检索。

编号由记录者显式填写，实验编号在项目内唯一，CSV 编号在实验内唯一。新增内容使用尚未使用的编号，不随排序、删除或改名重新编号。机器引用使用 ID，界面显示例如：

`Dexterity Study · 实验 003「调整观测」· CSV 02「评估结果」· 成功率`

图表序列键由项目 ID、实验 ID、CSV ID、指标 ID 组成，不能只用可能重名的标题或文件名。

## 页面

### 板块列表

复用 Archive/Card/Series 的现有样式与逻辑。每个项目一张卡片，展示标题、单行摘要、复现/改进标签、更新时间、实验数量、第一张正文图片（有则展示）。默认按更新时间倒序。

提供全文检索，以及类型、Topic、Tag、Series、月份、语言和状态筛选。项目状态为 `planned`、`running`、`completed`、`blocked`。项目与实验名称、编号、CSV 标题、指标名称也纳入索引；不把完整 CSV 数字序列塞入全文索引。

### 项目详情

两个可链接的页签：

1. **方法与复现笔记**：Markdown 正文、框图、公式、代码、目录、Series 和来源链接。
2. **实验结果**：实验列表、配置与结果摘要、关联 CSV 图表、视频，以及“数据对比”区域。

每次实验展示类型、编号、状态、日期、说明，以及可选的代码 commit、seed、硬件、数据集/任务、配置文件路径。未知值留空，不自动编造。

结果页的“数据对比”默认以当前项目为起点，但数据源选择器可以访问全部已发布实验项目。所有实验控件支持中文/英文界面、深浅主题和移动端布局。

### 数据对比

选择路径为“项目 → 实验 → CSV → 指标”，可搜索项目/实验/文件标题，也可通过稳定编号辨认条目。选中项作为可移除的曲线项显示，保留完整来源名称。

支持同一 CSV 的多个指标、同一实验的多个 CSV，以及不同项目/实验之间的对比。复现与改进均可选择。每条曲线颜色稳定，支持独立显示/隐藏，图例、悬停提示和导出均保留来源。

不同采样步数和曲线长度按各自真实横坐标绘制，不按行号强行对齐、不补零、不自动插值。不同横轴语义或纵轴单位的数据分成独立图面板，并提示分组依据；不将不同量纲静默叠在同一坐标轴上。单位换算应显式整理到 CSV/元数据，不通过猜测执行。

第一版不提供跨 seed 自动均值/方差、不直接读取 TensorBoard event 文件、不提供训练进程实时连接。目标是实现可交互的已保存实验曲线查看器。

## CSV 与坐标映射

每份 CSV 显式描述横轴和一个或多个纵轴。内部映射配置负责关联原始列、显示名称、单位与比较语义，不要求 CSV 列名叫 `step` 或 `reward`。

列选择支持两种方式，二选一：

- `column: "原始列名"`：适用于带表头的 CSV。
- `columnIndex: 3`：按从 1 开始的列号选择，适用于无表头或重名列。

横轴额外支持 `rowNumber: true`：没有真实横坐标时使用从 1 开始的数据记录序号，界面明确标注其含义，不伪装成训练步数。

CSV 格式配置包含 `delimiter`、`headerRow`、`dataStartRow`。行号按 CSV 逻辑记录从 1 计数，引号包裹字段中的换行不另算一行。默认逗号分隔、第一条记录为表头、第二条记录起为数据；无表头用 `headerRow: null` 和 `dataStartRow: 1`。支持 UTF-8 BOM、CRLF、带引号字段、引号转义、科学计数法。数值使用点号作小数点，不猜测地区数值格式。

`label` 决定图中显示的名字；`unit` 决定单位；`quantity` 是跨文件比较时使用的规范键，例如两份分别名为 `global_step` 和 `iteration` 的列，只有记录者确认含义一致后才都配置为 `quantity: training-step`。

以下仅为格式示意，不是实际运行结果：

```yaml
experiments:
  - id: baseline-seed42
    number: 1
    title: 原方法基线
    kind: reproduction
    status: completed
    date: "2026-10-12"
    seed: 42
    summary: 原方法在指定设置下的一次运行。
    csvs:
      - id: evaluation
        number: 1
        title: 验证集评估
        path: runs/baseline-seed42/evaluation.csv
        delimiter: ","
        headerRow: 1
        dataStartRow: 2
        x:
          column: "iteration_count"
          label: 训练迭代
          quantity: training-iteration
          unit: iteration
        metrics:
          - id: success-rate
            column: "evaluation/success_fraction"
            label: 成功率
            quantity: success-rate
            unit: fraction
          - id: completion-time
            columnIndex: 4
            label: 完成耗时
            quantity: completion-time
            unit: s
```

对不存在的列、重复 ID/编号和附件缺失给出项目、实验及文件级别的清楚报错。表头重名时要求使用列号，不静默选第一列。缺失/非有限数值不会变成 0：无效横轴的记录跳过并计数，无效纵轴产生曲线缺口。有效点按横坐标稳定排序；重复横坐标保留原顺序，不做隐式平均。

## 图表交互与计算

- 加载选中的 CSV 后在浏览器内解析和绘图，按需加载图表依赖与数据，不一次加载全部项目的数据。
- 横轴按每份 CSV 的配置映射；纵轴可选择该 CSV 声明的一个或多个指标，显示用户配置的名称和单位。
- 平滑：EMA 滑块范围 0–0.99，默认 0（原始值）。递推为 `s[0] = y[0]`，`s[i] = w*s[i-1] + (1-w)*y[i]`；曲线缺口后重新初始化。按完整序列计算后再缩放，不随可视区变化重算。
- 显示原始曲线/平滑曲线；启用平滑时原始数据可作为淡线参考。悬停区分原始值与平滑值，标注算法和当前系数。
- 框选缩放、拖动/滑动范围、复位、悬停读数、图例显示/隐藏和全屏/放大查看。
- 提供 PNG 图表导出及原始 CSV 下载。导出图片保留当前坐标标签、来源图例和平滑说明。
- 若为绘图性能进行采样，只影响显示，保留极值并明确标注；原始 CSV 下载与平滑计算不使用被采样的数据。首版性能验收使用每文件 10 万行、同时 6 条曲线的确定性测试数据；测试数据明确标为测试用途。
- 读取失败或没有数值数据时显示具体错误，不呈现看似有效的空白“成功”图。

## 文件组织与附件

```text
content/experimentrecord/<project-slug>/
  index.md
  experiments.yaml
  runs/<experiment-id>/
    evaluation.csv
    config.yaml
  images/
    method.png
  videos/
    evaluation.mp4
    evaluation-poster.jpg
```

`index.md` 复用现有文章必填 frontmatter，增加项目类型集合和项目状态。`experiments.yaml` 保存实验、CSV 映射和视频清单。实验结果和 CSV 索引由构建从该清单生成，不维护第二份手写索引。

附件路径相对于项目目录，构建只复制被正文或清单引用的公开附件。草稿项目及其 CSV、图像、视频不得进入公开索引或构建输出。CSV、视频和配置附件与正文图片一样兼容 GitHub Pages 的 `/ResearchStream/` 子路径。

视频使用浏览器原生播放器，支持封面、控件、说明以及关联实验；默认不自动播放，使用 `preload="metadata"`。支持项目内 MP4/WebM 和显式 HTTP(S) 视频地址。外部视频的可用性由来源决定。

已访问页面及已加载的同源 CSV/图片支持离线重读；不自动预缓存所有实验 CSV。视频不进入自动离线缓存，避免大文件下载以及 Range 请求缓存问题，界面说明视频需要联网。不提交模型权重、训练缓存、原始海量日志或私密凭据。

## README 与本地 AI 记录规范

README 增加板块说明、目录结构、元数据示例、CSV 坐标映射说明、跨项目选择方式、视频和离线边界，以及本地检查和 Git 发布步骤。提供可以直接复制的项目笔记与实验清单模板。

必须写入的核心描述：

> 复现笔记应完整记录方法整体框架，以及每一步实际操作、执行命令、修改内容和这样做的原因。区分原方法、复现修正与个人改进；保留失败尝试和未解决问题，不得将推测或未运行的实验写成已验证结果。

本地 AI 更新既有项目时保留项目、实验、CSV 和指标 ID，不因标题变更或加入新运行而重新编号。每次实验说明配置差异、评价协议和真实结果。新增 CSV 必须核对实际列名/列号、横轴含义、纵轴单位和数据范围；不能依据文件名猜测。

文稿与相关数据一起提交，通过现有 Actions 构建后发布。先验证引用、映射和页面，再明确列出暂存文件，不使用 `git add .`。只在 Actions 和线上核验通过后报告已发布。遵循 `coding_protocal.md`，维护 CHANGELOG 并留下清晰提交。

## 集成范围与验收

复用现有内容集合、文章布局、筛选、搜索、首页时间线和推荐阅读。方法笔记参与这些入口；每次实验在项目内管理，不将一份 CSV 生成一篇首页文章。Series 可连接 PaperPost、LearningWall 与 experimentRecord。

新增模块仅负责实验清单验证、附件与索引输出、CSV 数据处理、结果与比较界面。图表依赖选择在实施计划中完成，不改造无关架构。

核心验收：

1. 两个不同项目、各两次实验，每次多个 CSV；分类、稳定编号、索引与跨项目选择准确。
2. 列名映射、列序号映射、无表头与行号横轴正确；自定义中文标签、单位和图例显示正确。
3. 多曲线独立坐标、不等长数据、缺失值、EMA 结果、缩放复位正确，不伪造对齐数据。
4. 不同量纲/横轴语义分图，图例可追溯到项目、实验、CSV、指标。
5. CSV 下载、PNG 导出、图片和原生视频在子路径部署下可用。
6. 深浅主题、中英文控件、手机布局和键盘操作可用；图表外提供可读的来源和状态文本。
7. 草稿无公开附件；断网可读已缓存笔记和已加载 CSV，视频不自动进入缓存。
8. 既有 PaperPost、LearningWall、Series、搜索、每日导入和部署检查继续通过。

当前本地 `agent_dev` 落后于远端 `main`；远端已有后续日报和说明更新。实施前先以干净工作区整合最新远端内容，保留已发布内容，再开始产品修改。本设计阶段不改变网站行为或发布配置。
