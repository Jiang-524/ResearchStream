<a id="changes"></a>
## 复现与修改日志

每次操作追加一条；保留失败和修复历史。下面是单条记录结构，按实际执行顺序填写。

### YYYY-MM-DD HH:mm:ss +08:00 · 简短操作标题

- **状态与关联实验**：计划/已执行/失败/已核验；关联稳定实验编号和 ID。
- **当时问题与目标**：观察到什么，为什么做本次操作。
- **具体改动**：文件链接、函数/类、关键行号、修改前后行为和必要的短 diff。未修改代码的操作也记录命令和配置变化。
- **执行位置与命令**：机器/环境、cwd、完整可复现命令；不记录 token 或密码。
- **为什么这样改**：对应方法的哪部分，预期如何影响计算、稳定性或指标，为什么选择这个方案。
- **实际输出与核验**：退出状态、关键日志、输出文件本地链接、检查方法；尚未验证则写明。
- **代码/配置证据**：commit 或本地 patch 路径、配置快照、随机种子；不要只引用会被覆盖的 latest 文件。
- **结论与后续**：已确认的事实、仍不确定的解释、下一步行动。
